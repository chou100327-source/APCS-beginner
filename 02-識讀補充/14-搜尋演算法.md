## 一、線性搜尋（Linear Search）

**想法**：從頭到尾一個一個比，找到就停。

```python
a = [7, 3, 9, 4, 1]
target = 9
pos = -1                    # -1 表示還沒找到
for i in range(len(a)):
    if a[i] == target:
        pos = i
        break
print(pos)                  # 2
```

| i | `a[i]` | 等於 9 嗎 | 動作 |
|---|---|---|---|
| 0 | 7 | 否 | 繼續 |
| 1 | 3 | 否 | 繼續 |
| 2 | 9 | 是 | `pos = 2`，break |

- 最好情況：第一個就找到（1 次）。
- 最差情況：在最後或不存在（n 次）。→ **O(n)**
- **資料不需要排序**。

Python 內建寫法：

```python
a = [7, 3, 9, 4, 1]
print(9 in a)               # True
print(a.index(9))           # 2   找不到會 ValueError
print(a.count(3))           # 1
```

## 二、二分搜尋（Binary Search）

**前提：資料必須已經由小到大排好。**

**想法**：每次看「中間那個」，比目標大就丟掉右半邊、比目標小就丟掉左半邊，範圍每次砍一半。

```python
a = [1, 3, 5, 7, 9, 11, 13]
target = 11
lo, hi = 0, len(a) - 1
while lo <= hi:
    mid = (lo + hi) // 2
    print("lo", lo, "hi", hi, "mid", mid, "值", a[mid])
    if a[mid] == target:
        print("找到，索引", mid)
        break
    elif a[mid] < target:
        lo = mid + 1          # 目標在右半邊
    else:
        hi = mid - 1          # 目標在左半邊
else:
    print("沒找到")
```

輸出：

```
lo 0 hi 6 mid 3 值 7
lo 4 hi 6 mid 5 值 11
找到，索引 5
```

追蹤表（找 11）：

| 輪 | lo | hi | mid | `a[mid]` | 比較 | 下一步 |
|---|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | 7 | 7 < 11 | `lo = mid + 1 = 4` |
| 2 | 4 | 6 | 5 | 11 | 找到 | 結束 |

[[viz:binary]]

### 找不到的例子（找 6）

| 輪 | lo | hi | mid | `a[mid]` | 動作 |
|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | 7 | 7 > 6 → `hi = 2` |
| 2 | 0 | 2 | 1 | 3 | 3 < 6 → `lo = 2` |
| 3 | 2 | 2 | 2 | 5 | 5 < 6 → `lo = 3` |
| 結束 | 3 | 2 | | | `lo > hi`，範圍空了，沒找到 |

### 為什麼是 `lo = mid + 1`、`hi = mid - 1`？

`mid` 那一格已經比過了，一定不是答案，所以要跳過它。如果寫成 `lo = mid`，範圍有時不會縮小，變成**無窮迴圈**。

### 最多比較幾次？

每次範圍減半：n → n/2 → n/4 → … → 1，約 **⌊log₂n⌋ + 1** 次。

| n | 最多比較 |
|---|---|
| 7 | 3 |
| 100 | 7 |
| 1000 | 10 |
| 1,000,000 | 20 |

## 三、兩種搜尋比較

| | 線性搜尋 | 二分搜尋 |
|---|---|---|
| 前提 | 無 | **必須已排序** |
| 時間複雜度 | O(n) | O(log n) |
| 1000 筆最多比較 | 1000 次 | 約 10 次 |
| 適用 | 資料少、沒排序、只找一次 | 資料多、已排序、要找很多次 |

## 四、用二分搜尋找「第一個 ≥ 目標」的位置

這是很常見的變形（例如找名次、找插入位置）：

```python
a = [1, 3, 3, 5, 8]
target = 3
lo, hi = 0, len(a)         # 注意 hi 是 len(a)，答案可能在最後面之後
while lo < hi:
    mid = (lo + hi) // 2
    if a[mid] < target:
        lo = mid + 1
    else:
        hi = mid
print(lo)                  # 1   第一個 >= 3 的位置
```

追蹤：

| 輪 | lo | hi | mid | `a[mid]` | 動作 |
|---|---|---|---|---|---|
| 1 | 0 | 5 | 2 | 3 | 3 不小於 3 → `hi = 2` |
| 2 | 0 | 2 | 1 | 3 | 不小於 → `hi = 1` |
| 3 | 0 | 1 | 0 | 1 | 1 < 3 → `lo = 1` |
| 結束 | 1 | 1 | | | 答案 1 |

## 五、五分鐘小練習

```quiz
Q: 使用二分搜尋的前提是什麼？
* 資料必須已經排序
- 資料必須全為正整數
- 資料不能有重複
- 資料量要夠小
E: 二分搜尋靠「跟中間值比大小來決定往哪半邊找」，沒排序就沒有方向性，結果會錯。

Q: 1000 筆已排序資料用二分搜尋，最多大約要比較幾次？
* 約 10 次
- 約 100 次
- 1000 次
- 500 次
E: 每次砍半，2¹⁰ = 1024，所以約 log₂1000 ≈ 10 次。線性搜尋最差要比 1000 次。

Q: 二分搜尋中算出 `mid` 後，若 `a[mid] < target`，該怎麼做？
* `lo = mid + 1`（往右半邊找）
- `hi = mid - 1`
- 直接回傳 mid
- `lo = mid`
E: 中間值比目標小，目標一定在右半邊，而 mid 已比過可以排除；寫成 lo = mid 可能無窮迴圈。

Q: 在 `[1, 3, 5, 7, 9, 11, 13]` 中二分搜尋 11，第一次的 mid 對應的值是？（lo = 0、hi = 6、mid = (lo + hi) // 2）
* 7
- 5
- 9
- 11
E: mid = (0 + 6) // 2 = 3，a[3] = 7，比 11 小，所以往右半邊找。

Q: 線性搜尋在最差情況下要比較幾次（n 筆資料）？
* n 次
- 1 次
- log n 次
- n² 次
E: 目標在最後一個或根本不存在時，要把全部都看過。

Q: 二分搜尋的時間複雜度是？
* O(log n)
- O(n)
- O(1)
- O(n²)
E: 每次把搜尋範圍砍一半，約 log₂n 次。

Q: 下列哪種情況比較適合用線性搜尋？
* 資料沒有排序，而且只要找一次
- 資料有 100 萬筆且已排序，要查很多次
- 要在排序好的資料找 mid
- 資料已經排好且很大
E: 沒排序就不能用二分搜尋；排序本身也要時間，只找一次時直接線性搜尋最省事。

Q: 二分搜尋迴圈 `while lo <= hi:` 結束後 `lo > hi`，代表？
* 範圍已經空了，沒有找到
- 找到了
- 資料有重複
- 程式出錯
E: lo > hi 表示候選範圍不存在，目標不在串列中。
```

## 六、常見錯誤

- **資料沒排序就用二分搜尋**：結果會錯，而且不會報錯。
- **`lo = mid` 或 `hi = mid`（在 `lo <= hi` 版本）**：可能卡在原地變無窮迴圈；要 `mid ± 1`。
- **迴圈條件寫成 `lo < hi` 卻搭配 `hi = len(a) - 1`**：會漏掉 `lo == hi` 的最後一格。
- **用 `a.index(x)` 找不存在的值**：會 `ValueError`，要先用 `in` 判斷。
- **`mid = (lo + hi) / 2`**：`/` 得到小數，不能當索引，要用 `//`。
