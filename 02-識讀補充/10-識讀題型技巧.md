# 10 程式識讀題型技巧：追蹤・填空・除錯（識讀補充 ★ 優先度 3）

> **為什麼排第三**：官方說明程式識讀是單選題，題型有 5 種：**程式運行追蹤、程式填空、測試與除錯、效能分析、計算邏輯分析**。前面你學的語法是「材料」，這一單元教的是「看到題目怎麼下手」。學會方法，同樣的觀念能多拿很多分。（效能分析在下一單元專門講。）

> **本單元學完你要能做到**
> 1. 用追蹤表手動執行一段程式，不漏步驟
> 2. 看到「填空」題，用「代入驗證」找出正確選項
> 3. 看到「除錯」題，用「邊界值」與「小例子」找出錯誤的那一行
> 4. 面對「計算邏輯」題，把程式翻成白話、找規律
> 5. 掌握單選題的作答策略

## 一、題型 1：程式運行追蹤（code tracing）

**問題長相**：給一段程式（可能有輸入），問輸出、某個變數的最終值、某行執行幾次。

### 做法：追蹤表

1. 把**所有會變的變數**寫成表頭。
2. 一次執行**一行**，只改有變的那格，其他照抄。
3. 迴圈：每跑一輪寫一列；`if` 要註明成立與否。
4. 最後再看題目問什麼，不要半途就「憑感覺」猜。

**範例**：

```python
a = 5
b = 2
while a > 0:
    a -= b
    b += 1
print(a, b)
```

| 輪 | 開始時 a | 開始時 b | `a > 0`? | 做完後 a | 做完後 b |
|---|---|---|---|---|---|
| 1 | 5 | 2 | 是 | 3 | 3 |
| 2 | 3 | 3 | 是 | 0 | 4 |
| 3 | 0 | 4 | 否 | 結束 | |

輸出 `0 4`。注意第 2 輪 `a -= b` 用的是**更新前**的 `b = 3`（`b += 1` 在後面）。

### 追蹤的小心點

- **先後順序**：`a -= b` 和 `b += 1` 誰在前，結果完全不同。
- **邊界**：`>` 與 `>=`、`range` 含頭不含尾。
- **同一個名字**：函式裡的區域變數和外面同名時，是兩個不同的變數。

## 二、題型 2：程式填空（code completion）

**問題長相**：程式有一處留白（①、空格），問該填什麼才能完成指定功能。

### 做法：代入驗證

不要只憑感覺選，把**每個選項填進去**，用一組簡單的資料跑一遍：

```python
# 功能：算出串列 nums 中最大的數
best = nums[0]
for x in nums:
    if ______:
        best = x
print(best)
```

選項：(A) `x < best`　(B) `x > best`　(C) `x == best`　(D) `x != 0`

用 `nums = [3, 9, 2]` 代入：

| 選項 | 追蹤 | 結果 |
|---|---|---|
| (A) `x < best` | best 一開始 3；x=3 否；x=9 否；x=2 是 → best=2 | 印 2（變成最小）✘ |
| (B) `x > best` | x=3 否；x=9 是 → best=9；x=2 否 | 印 9 ✔ |
| (C) `x == best` | 只有 x = 3 時成立，best 還是 3 | 印 3 ✘ |
| (D) `x != 0` | 每個都成立，最後 best=2 | 印 2 ✘ |

答案 (B)。

### 填空的線索

| 看到 | 通常是 |
|---|---|
| 累加變數 `total` 前面空格 | `total += …` |
| 迴圈範圍的空格 | 注意含頭不含尾 `range(1, n + 1)` |
| 迴圈後面接 `else`／判斷「找不到」 | 用 `for…else` 或旗標變數 |
| 兩個變數交換 | 暫存變數，或 `a, b = b, a` |
| 遞迴缺的那一行 | 看「終止條件」與「縮小規模」 |

## 三、題型 3：測試與除錯（code testing and debugging）

**問題長相**：程式「有 bug」，問：哪一行錯？為什麼對某組輸入會錯？該怎麼修？

### 做法：找「會讓它出錯的輸入」

1. 先用**題目給的範例輸入**跑一遍，確認程式在「一般情況」下的行為。
2. 再試**邊界輸入**：最小值（0、1、空）、最大值、全部相同、負數、剛好等於邊界。
3. 對照選項敘述，哪一種輸入造成的結果和預期不同。

**範例**：想判斷 `n` 是不是質數：

```python
def is_prime(n):
    for d in range(2, n):
        if n % d == 0:
            return False
    return True
```

問：下列哪個輸入會得到**錯誤**結果？ 

| 輸入 | 追蹤 | 正確答案 | 程式回傳 |
|---|---|---|---|
| 7 | 2~6 都除不盡 | 質數 | True ✔ |
| 9 | d=3 時整除 | 不是質數 | False ✔ |
| 2 | `range(2, 2)` 是空的 | 質數 | True ✔ |
| **1** | `range(2, 1)` 是空的 | **不是質數** | **True ✘** |

bug：沒有處理 `n < 2`。修法：開頭加 `if n < 2: return False`。

### 常見 bug 清單（遇到除錯題先對照）

| bug 類型 | 例子 |
|---|---|
| 邊界差一（off-by-one） | `range(1, n)` 應為 `range(1, n + 1)`；`<` 應為 `<=` |
| 累加器初始值錯 | 連乘從 0 開始、`total = 0` 寫在迴圈裡 |
| 條件順序錯 | 分段判斷從小的寫起，後面永遠輪不到 |
| `=` 與 `==` | 語法錯誤 |
| 沒有更新迴圈變數 | `while` 無窮迴圈 |
| 縮排錯誤 | `return` 或 `print` 縮排層級不對 |
| 浮點誤差 | 用 `==` 比較小數 |
| 沒有處理空資料 | `max([])` 出錯、`nums[0]` 索引超出 |

## 四、題型 4：計算邏輯分析（computational logic）

**問題長相**：不一定寫程式，而是一段規則、流程或數學推理題：計數、規律、機率、遊戲規則、真值表……

### 做法

1. **把規則翻成白話**，再用 2~3 個**小數字**手算，找出規律。
2. 不要一開始就套大數字；先算 n = 1, 2, 3 再推。
3. 遇到邏輯條件：列真值表。遇到計數：列出所有情形或用乘法原理。

**範例**：每次可以走 1 階或 2 階，走到第 4 階有幾種走法？

| 階數 n | 走法數 | 說明 |
|---|---|---|
| 1 | 1 | (1) |
| 2 | 2 | (1,1)(2) |
| 3 | 3 | 第 3 階 = 第 2 階的走法 + 第 1 階的走法 |
| 4 | 5 | 第 4 階 = 第 3 階 + 第 2 階 = 3 + 2 |

規律：每一項等於前兩項相加（費氏數列）。

## 五、單選題的作答策略

1. **先看題目問什麼**（輸出？變數值？哪一行錯？），圈起來。
2. **能算就算，不要猜**：追蹤表通常不超過 10 行，算一次最可靠。
3. **排除法**：有些選項一看就不可能（型態不對、負數變正數等）。
4. **注意陷阱選項**：題目的錯誤選項多半是「常見錯誤想法」的結果——例如 `-7 // 2` 的 -3、`int(2.9)` 的 3、把 `range` 的尾巴算進去。算出的答案若正好是某個選項，不代表對；要確認自己沒落入同一個陷阱。
5. **時間分配**：卡超過 2 分鐘先標記、跳下一題，最後回來。

## 六、五分鐘小練習

```quiz
Q: 下列程式輸出什麼？`a = 5; b = 2` / `while a > 0:` / `    a -= b` / `    b += 1` / `print(a, b)`
* 0 4
- 0 3
- -1 4
- 3 3
E: 追蹤表：第 1 輪 a=3、b=3；第 2 輪 a=3-3=0、b=4；a > 0 不成立結束。

Q: 要找串列的最大值，擂台法的條件應填入？`best = nums[0]` / `for x in nums:` / `    if ____:` / `        best = x`
* x > best
- x < best
- x == best
- x != 0
E: 有人比現在的擂主大就換人。x < best 會找到最小值。

Q: 判斷質數時對 n = 1 回傳 True，是因為漏掉了什麼處理？
* n < 2 的情況
- n 為偶數的情況
- n 很大的情況
- n 為負數以外的情況
E: 1 不是質數；range(2, 1) 是空的所以迴圈一次都不跑，直接 return True。

Q: 除錯題最有效率的第一步是？
* 用範例輸入先跑一遍，再試邊界輸入
- 把整段程式重新寫一遍
- 隨便猜一個選項
- 只看變數名稱
E: 先確認一般情況，再用最小值、空資料、剛好等於邊界等特殊輸入找破綻。

Q: 程式填空題時，最可靠的驗證方式是？
* 把每個選項代入，用一組簡單的資料實際追蹤
- 選看起來最長的
- 選最短的
- 看選項字母
E: 代入驗證比憑感覺可靠，用小資料（2~3 個元素）追蹤即可。

Q: 每次走 1 階或 2 階，走到第 5 階共有幾種走法？（第 n 階 = 第 n-1 階 + 第 n-2 階，前兩階 1、2）
* 8
- 5
- 7
- 10
E: n=1→1、n=2→2、n=3→3、n=4→5、n=5→8。
```

## 七、常見錯誤

- **追蹤跳步**：用心算一次做好幾行，漏掉變數更新的先後順序。
- **只追蹤一般情況**：除錯題要特別測邊界輸入。
- **只憑直覺選答案**：能代入就代入。
- **看錯題目問什麼**：問的是「最後一個值」還是「總共印出幾次」。
- **忽略陷阱選項**：題目刻意放了「落入常見錯誤」的選項。
